## 2. What the project is

A browser-based 3D gravitational sandbox. A Python/FastAPI backend owns all physical state and integrates it with **REBOUND**
(not written by us). A React + Three.js frontend renders what the backend reports. Hackathon origin: 36 hours; since then an
extensive collision engine, a multi-universe lab, Solar System presets and an Orbit Lab experiment were added.

Repository size: 500 tracked files (backend 121, frontend 255, tests 75, context 35, scripts 5).

  (`>=5.2,<5.3`). Local vs CI pydantic/FastAPI differ and change which tests pass. `pytest` and `httpx` are listed as runtime
  requirements. Frontend has `package-lock.json` (good). CI uses Node 20; local Node 24 also works.

- **KD-5: Playwright's pinned Chromium may be missing**; the config supports `PW_CHROMIUM_PATH`, but this is only documented in
  `context/`. The README now documents it.

  (e.g. "presets stay legacy-merge", "not pushed or merged"). Banners now point here; contents were not rewritten.
- **KD-7: bundle size** 1.3 MB main chunk (no code splitting).
- **KD-8: `.playwright-mcp` console log was tracked** (generated clutter); untracked and ignored in this consolidation.

Technical debt and scientific limitations beyond the above: collision science is provisional and unreviewed; `simulation.py` is
1,159 lines carrying engine, history and collision orchestration; frontend/backend material tables are twins that must be kept in
sync by hand (`frontend/src/sim/defaultMaterial.ts` vs `backend/impact/materials.py`); everything is in-memory and single-process;
performance beyond the existing 64-body frame profile and 200-body step-latency test is unmeasured.

State consistency and concurrency: one lock per engine serialises writes; reads return the last committed state; activation epoch
guards cross-universe races (tested). The frontend's lookahead buffer is discarded on reset/pause (tested in unit tests); behaviour
under backend restart is surfaced to the user but not persisted.

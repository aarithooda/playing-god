## Simulation stall investigation and resilience fix, PR open (2026-10-24) — newest
- **Incident:** a long run "stopped advancing" at ~4.8 simulated years; after a browser refresh the scene stayed on "Connecting to the simulation backend…" while the header said "Backend: connected".
- **Confirmed causes (evidence in `WORKLOG.md`):** (1) *Numerical:* the still-running backend (pid 5328, started 01:27, **running pre-D-011/D-012 code**, `8d7ab36` layout) was inside native `integrate` for a `POST /step` (`dt=1e7`, `t0=1.515e8 s` = 4.80 yr) with IAS15's internal dt collapsed to ~1e-25 s and `t` frozen at 155344829.88062295 s; the recovered state is three equal masses on a line (the middle body's net force cancels by symmetry), exactly the wedge fixed by D-011. Replayed out of tree: the old code never returns from that state (60 s cap), current `main` completes it in 2.3 s with the two expected mergers. (2) *Amplification:* the step held the one service lock; `GET /state` took the same lock and queued forever, `/healthz` takes no lock, so health stayed "connected". (3) *Frontend:* no request timeouts and one FIFO queue, so a hung request blocked the initial load, Retry and every later action forever; the load message said "Connecting" even though health was ok.
- **Fix (this branch, frontend + backend, no physics change):** reads (`/state`, `/events`) return the last committed state without waiting for a step; mutations and steps wait a bounded time, then 503 "busy"; API client timeouts (reads 8 s, writes 35 s); distinct loading/error wording for "backend reachable, simulation not responding" with Retry; an unknown-outcome step is followed by a re-read of the committed state; Play still stops on the first failure (no retry loop). Decision D-021 accepted by the owner, who verified and directed the merge of PR #10 (no independent review; one-PR exception).
- **Verified (fresh runs):** backend `pytest` 265 passed (259 + 6 new, including the incident state and read/mutation behaviour during a blocked step); `tsc` clean; `vitest` 168 passed (+12: client timeouts, hook recovery, App states); `npm run build` OK. Real server with an artificially stuck step: `/healthz`, `/state`, `/events` answer in ~0.2 s with the pre-step state and a write gets 503 after ~3 s; in the browser a refresh during a stuck step loads the scene immediately and Step shows the busy message in ~3 s with the time unchanged.
- **Not reproduced / limitations:** the *original initial conditions* are unavailable; the reproduction uses the state recovered from the stuck process (mid-run, t = 1.5534e8 s), not the first minutes of the run. The 35 s UI step-timeout banner and resync are covered by unit tests, not by a live 35 s browser wait. A single native `integrate` that never reaches REBOUND's heartbeat still cannot be interrupted in-process. **The old backend (pid 5328) is still running and stuck; it must be restarted to pick up D-011/D-012 and this fix, which clears the in-memory universe. I did not stop it.**

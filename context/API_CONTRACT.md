# API Contract (v1, production REBOUND simulation)
Source of truth for schemas: `backend/models.py` (Pydantic); behaviour: `backend/simulation.py`, `backend/collisions.py`. Update this file in the same change as any API change.

**Status legend:** ✅ implemented (tested) · 🕓 planned (does NOT exist yet).

## Conventions
- **Units (SI, always, in every field):** mass `kg`; radius and position `m`; velocity `m/s`; simulation time `s`; G = `6.67430e-11 m^3 kg^-1 s^-2`. Unit is in the field name suffix (`massKg`, `radiusM`, `positionM`, `velocityMPerS`, `simulationTimeS`).
- **Coordinates:** one fixed, right-handed Cartesian frame (x × y = z). Positions and velocities share this frame. The origin is the simulation origin (not tied to any body). The frontend may scale/offset *rendered* distances for visualization but must never alter or send scaled values as API physics values.
- **Numbers:** JSON numbers, finite only. NaN/Infinity (and overflow such as `1e999`) are rejected.
- **IDs:** generated by the backend (`body-<12 hex>`), unique, never reused, stable across reads. Clients must not send `id`.
- **Colors:** `#RRGGBB` (6 hex digits, case-insensitive; stored as sent).
- **Unknown request fields are rejected** (422).
- **Request bounds (422 outside):** `massKg` ∈ (0, 1e45]; `radiusM` ∈ (0, 1e15]; each `positionM` component |.| ≤ 1e18; each `velocityMPerS` component |.| ≤ 299792458 and total speed < c; `dtS` ∈ [1e-6, 1e8]; `name` 1–64 chars. Responses are not bounded: evolved state is reported as the engine has it.
- **Error shapes:** 422 `{"detail": [{"loc": ["body","massKg"], "msg": "...", "type": "greater_than"}]}` (validation); 404 / 409 / 500 / 503 `{"detail": "<message>"}`.
- **Base path:** backend serves `/api/v1/...` itself. Note: the Vite dev proxy currently *strips* `/api` (see Assumptions).

### Body
```json
{"id":"body-3f9a1c2b7d4e","name":"Earth","massKg":5.972e24,"radiusM":6.371e6,
 "positionM":{"x":1.496e11,"y":0.0,"z":0.0},"velocityMPerS":{"x":0.0,"y":29780.0,"z":0.0},"colorHex":"#3b82f6"}
```
`name`: 1–64 chars (display only; ids identify bodies).

### SimulationState
`{"status": "paused" | "running", "simulationTimeS": number, "bodies": [Body], "diagnostics": Diagnostics}` — bodies in creation order (a merge survivor keeps its place in the order). **`status` is always `"paused"`**: the server never advances time on its own. Play is the client calling `POST /simulation/step` repeatedly; Pause is it stopping. `"running"` is reserved and never returned.

### Diagnostics
Every SimulationState (state, step and reset responses; not the body or events endpoints) carries `diagnostics`, computed from the **same** body list and under the same lock as `bodies`, so it describes exactly that state (D-013). Model: point masses, Newtonian gravity, G = 6.67430e-11, one inertial right-handed frame (D-010). The JSON below uses illustrative values, not output of a particular run.
```json
{"diagnostics":{"version":1,"totalMassKg":3000.0,"totalMomentumKgMPerS":{"x":0.0,"y":0.0,"z":0.0},
 "kineticEnergyJ":1333.3,"potentialEnergyJ":-0.00013,
 "angularMomentumAboutOriginKgM2PerS":{"x":0.0,"y":0.0,"z":-666.7},"bookedSpinKgM2PerS":{"x":0.0,"y":0.0,"z":0.0}}}
```
| Field | Units | Definition |
|---|---|---|
| `totalMassKg` | kg | Σ mᵢ |
| `totalMomentumKgMPerS` | kg·m/s | Σ mᵢvᵢ |
| `kineticEnergyJ` | J | Σ ½mᵢ‖vᵢ‖² |
| `potentialEnergyJ` | J | −G Σᵢ<ⱼ mᵢmⱼ/‖rᵢ−rⱼ‖, zero at infinite separation (negative) |
| `angularMomentumAboutOriginKgM2PerS` | kg·m²/s | Σ mᵢ rᵢ×vᵢ about the fixed simulation origin (0,0,0), **not** the centre of mass |
| `bookedSpinKgM2PerS` | kg·m²/s | Σ of the spin vectors booked by mergers for the bodies that still exist (bookkeeping: no rotation dynamics, no spin energy) |
| `version` | — | Semantics version, always `1` (typed `Literal[1]` in the response model and the OpenAPI document). Additive fields do not bump it; redefining a field does. |

- **Undefined values:** each quantity is a finite number or JSON `null`; a vector is all-or-nothing. NaN/Infinity are never emitted. Empty and single-body systems are defined (empty sums are 0, U = 0). `potentialEnergyJ` is `null` if two centres coincide (the API cannot create this) or on overflow; any other quantity is `null` only on overflow.
- **Derive in the client:** total mechanical energy K+U, speed ‖v‖, distance between bodies, orbital + booked angular momentum (`angularMomentumAboutOrigin + bookedSpin`).
- **What is conserved (only when no body is added, patched or deleted, and no reset):** M and P through steps and mergers (≈1e-12 of Σ mᵢ‖vᵢ‖ for P; judge P against that scale, not ‖P‖); K+U between mergers (IAS15 drift ≈1e-10 relative in tests); L about the origin between mergers. A merger removes translational energy Q (`kineticEnergyLostJ`) and the pair's mutual potential, so **K+U is not conserved across a merger**, and moves μ(r_rel×v_rel) from orbital L into `bookedSpin`: **orbital L alone is not conserved across a merger, orbital L + booked spin is** (≈1e-6 in tests). Editing, adding, deleting or resetting changes the baseline; clients must re-baseline any drift display on those, on every event and after reset.
- **Not a complete energy budget:** U is the mutual energy of point masses (equal to the exterior energy of non-overlapping spheres; it excludes self-gravity). Booked spin carries no rotational energy, so post-merger K+U understates the energy of a physical remnant.
- **Precision:** sums use exactly-rounded `fsum` and are independent of body order. K and U can be ~1e33 J while K+U is ~1e29 J, so E carries an absolute error of ~2⁻⁵³·max(|K|,|U|). Doubles resolve ~3e-5 m at 1 AU, which limits U for close pairs far from the origin. L about the origin of a system far from it is dominated by bulk motion.
- **Failed, timed-out and reset:** a 500/503 step returns no diagnostics and the next read equals the pre-step values bit for bit (booked spin included). Reset returns the empty-system zeros. Reading diagnostics does not change the simulation.
- **Cost:** O(N²) pair sum; measured 3.7 ms median (compute) / 4.6 ms (whole snapshot) at N=200, no caching.
- Deferred (not in v1): centre of mass and L about it, per-body spin/KE/momentum, the cumulative energy-loss ledger, orbital elements.

### Event
```json
{"id":"evt-1","type":"merger","simulationTimeS":99.26,"estimatedContactTimeS":99.1185,
 "bodyIds":["body-a","body-b"],"resultBodyId":"body-a","resultMassKg":3000.0,
 "relativeSpeedMPerS":2.0,"kineticEnergyLostJ":1333.33,"spinAddedKgM2PerS":{"x":0,"y":0,"z":-666.67}}
```
- `type`: only `"merger"` exists. Every detected overlap is resolved as a perfectly inelastic merger (no bounce, no fragmentation), so a separate `collision` event would carry no extra information and is not emitted.
- `simulationTimeS`: engine time at which the overlap was **detected** (end of an internal integrator step). It is NOT the contact time. `estimatedContactTimeS` is a straight-line back-extrapolation (exact for gravity-free motion, otherwise accurate to the path curvature within one step; `null` if no estimate exists). Do not present either as an exact timestamp.
- `bodyIds` = `[survivor, absorbed]`; `resultBodyId` = survivor (the heavier body; ties: the engine's first particle). The absorbed id is deleted and never reused. The survivor keeps its id, name and colour and gets the combined mass, centre-of-mass position and velocity, and a volume-conserving radius.
- `kineticEnergyLostJ` = ½μv_rel² of translational energy; it is not conserved (there is no heat/internal-energy model, it is only summed in a server-side ledger). `spinAddedKgM2PerS` = orbital angular momentum μ(r_rel×v_rel) booked as remnant spin: bookkeeping only (no rotation, no spin energy, no tides).
- Event ids `evt-<n>` increase for the process lifetime (not reused after reset). The server keeps the latest 1000 events.

## Endpoints

### ✅ `GET /healthz`
Liveness probe. (Legacy `GET /health` has the same response.) Response 200: `{"status":"ok"}`.

### ✅ `GET /api/v1/simulation/state`
Authoritative snapshot (D-001). Response 200: SimulationState. Fresh server: `{"status":"paused","simulationTimeS":0.0,"bodies":[],"diagnostics":{<empty-system zeros>}}`.

### ✅ `POST /api/v1/bodies`
Add a body at the current simulation time. Request: Body without `id`. Response **201**: the Body with its generated `id`.
Errors: 422 (validation/bounds; unknown field including `id`); **409** if the new sphere would overlap an existing body (centre distance < r₁+r₂, because a zero-separation start corrupts the engine) or 200 bodies already exist.

### ✅ `PATCH /api/v1/bodies/{body_id}`
Partial update; any subset of `name, massKg, radiusM, positionM, velocityMPerS, colorHex` (vectors are replaced whole), at least one, none `null`; `id` is immutable. Physical changes take effect from the current simulation time. Response 200: the full Body.
Errors: 404 unknown (or merged-away) id; 422 validation (empty body, null, unknown field, bounds); 409 if the new position/radius would overlap another body. A rejected request changes nothing.

### ✅ `DELETE /api/v1/bodies/{body_id}`
Remove a body. Response 204, no body. Errors: 404 unknown id.

### ✅ `POST /api/v1/simulation/step`
Advance simulation time by `dtS` seconds using REBOUND IAS15 (bounds above; a larger request is a 422, so the client loops). Request `{"dtS": 3600.0}`.
Response 200: SimulationState plus
```json
{"status":"paused","simulationTimeS":3600.0,"bodies":[...],"diagnostics":{...},"advancedS":3600.0,"events":[Event, ...]}
```
`events` holds only events that occurred during this call (merged-away bodies are already missing from `bodies`; use `events[].bodyIds`). `advancedS` equals `dtS` up to rounding.
The step is transactional: if the engine raises, a collision callback fails or any state becomes non-finite, the state from before the call is restored and the response is **500** `{"detail":"simulation step failed and was rolled back: ..."}`. Requests are serialized by a lock (concurrent steps queue, never interleave).
**Wall-clock budget:** a step that has not finished within `PG_STEP_TIME_LIMIT_S` seconds (default 10) is stopped (checked between chunks and, through REBOUND's heartbeat, after every internal step, so a stalled engine is stopped too), rolled back exactly like a failed step, and answered **503** `{"detail":"step exceeded its 10 s wall-clock budget; state was not advanced (retry with a smaller dtS)"}`. Time, bodies, events and event ids are those from before the request. The replay after a rollback uses a different internal step grid (same physics to integrator accuracy, not bitwise identical; event detection timestamps can move by one internal step). An empty simulation is never timed out.
Errors: 422 bad `dtS`; 500 rolled back; 503 wall-clock budget exceeded (both leave the state untouched; the client should stop Play and may retry with a smaller `dtS`). There is no 409 "running" case: the server never runs by itself.

**Concurrency (D-021):** one lock serializes every mutation and step. **Reads never wait for it**: `GET /healthz`, `GET /api/v1/simulation/state` and `GET /api/v1/events` answer immediately while a step runs, and `state` returns the last *committed* state (the one before the running step; never a half-advanced state). A mutation (`POST/PATCH/DELETE` bodies, `step`, `reset`) that cannot get the lock within `step budget + 5 s` (15 s by default) fails with **503** `{"detail":"the simulation is busy (a step is still running); nothing was changed, try again shortly"}` and `Retry-After: 2`; nothing was changed, so retrying is safe. A client that times out waiting for a *write* does not know whether it ran: re-read `state` rather than assume. A single native `integrate` call that never reaches REBOUND's heartbeat still cannot be interrupted in-process (limitation; see `context/WORKLOG.md`, 2026-10-24 stall investigation).

### ✅ `POST /api/v1/simulation/reset`
Remove all bodies and events, time back to 0. Deterministic: the same inputs afterwards give the same results as a fresh server. Response 200: `{"status":"paused","simulationTimeS":0.0,"bodies":[],"diagnostics":{<empty-system zeros>}}`. Body ids are never reused; event ids continue counting.

### ✅ `GET /api/v1/events`
Response 200 `{"events":[Event, ...]}`, oldest first (latest 1000 since the last reset). Verified by `tests/test_events_endpoint.py`: empty shape, field set and values of head-on and grazing mergers, null `estimatedContactTimeS` at exact tangency, agreement with the step response, persistence across quiet steps and body edits/deletes, reset (log cleared, ids keep counting), rolled-back and timed-out steps (no event, id not consumed), the 1000-event cap, cascades. Only GET is allowed (405 otherwise).

## Universes (Simulation Lab, added in M1)
Spec: `context/specs/SIMULATION_LAB_SPEC.md`; design: `context/EXPERIMENT_01_IMPLEMENTATION_PLAN.md` sections 6-7. Each universe is an
independent backend-owned engine. One universe is **active** at a time (initially `uni-default`, epoch 1); every activation increments
the **activation epoch**. Only the active universe can be mutated or advanced, and a mutation must echo the epoch it was issued under.
The legacy routes above are unchanged and act on `uni-default`; their mutations answer 409 `universe_not_active` while another universe is active.
`Body` additionally carries `kind` (`"star"|"planet"`, default `"planet"`, patchable) and `catalogueEntryId` (provenance only, nullable).

Coded errors keep the `{"detail": ...}` shape and add `"code"`: 404 `universe_not_found` (detail says "deleted" for a deleted id),
409 `universe_not_active`, `stale_activation`, `stale_revision`, `deactivated_during_step`, `active_universe_delete`, `universe_limit` (8 universes), `baseline_protected`.
Mutations: `?activationEpoch=<int>` is required (422 if missing); `&expectedRevision=<int>` is optional and rejects a duplicate/stale request.

| Route | Notes |
|---|---|
| `GET /api/v1/universes` | `{universes: [UniverseSummary], activeUniverseId, activationEpoch}` |
| `POST /api/v1/universes` | `{name?, source: {kind:"empty"}, activate?}` -> 201 `UniverseSummary` (presets: see `/presets`, M3) |
| `GET /api/v1/universes/{uid}` | `UniverseSummary` = `{id, name, role, presetId, experimentId, active, simulationTimeS, bodyCount, revision, status: "idle"|"mutating", lastFailure, createdAtIso, epochLabel, historyMode}` |

| `GET /api/v1/universes/{uid}/state`, `/events` | any universe; state = SimulationState + `universeId`, `revision` |
| `POST /api/v1/universes/{uid}/bodies`, `PATCH|DELETE .../bodies/{id}` | as the legacy routes, plus the epoch query |
| `POST /api/v1/universes/{uid}/step`, `/reset` | step response and reset state carry `universeId`, `revision`. **Reset returns the universe to its initial state**: empty for a sandbox, the loaded preset/experiment state otherwise; history returns to sample 0 under a new generation. |

### Snapshot guarantee (in-memory, this process only)
A snapshot is a REBOUND `Simulation.copy()` plus the service state (bodies, ids, names, colours, kinds, merger ledgers, events, history, controlled flag). Restore brings back the exact physical state and time. Continuation after a restore with the same sequence of `dtS` is **bit-identical** within one process (`tests/test_snapshots.py::test_snapshot_restore_bitwise_continuation`); this is not promised across restarts, machines, OS or REBOUND versions. Event ids are never reused. Failed-step rollback is unchanged (records rebuild, D-012: not bitwise).

### History
`{universeId, mode: "grid"|"step", sampleIntervalS, generation, firstIndex, nextIndex, droppedBefore, truncated, samples: [{index, simulationTimeS, segment, positionsM: {bodyId: [x,y,z]}}], bodies: {bodyId: {name, colorHex, radiusM, kind}}}`.
Recorded by the engine only. `grid` mode (presets, Orbit Lab): a sample at exactly k x interval (the engine lands on each); recording stops at 200,000 positions (`truncated`). `step` mode (sandbox): one sample per committed change (step, add, edit, delete), a ring that drops the oldest (`droppedBefore`). `segment` increases at physical edits, adds, deletes and mergers: never join points across it. Only committed samples are visible. `generation` changes on reset and restore; a request with another generation starts at `firstIndex`. Metadata is kept for bodies that later merged away.


`revision` is +1 per committed change and is present in every universe response. A step that is cancelled (switch), refused at commit
(stale epoch) or fails is rolled back completely: `lastFailure = {kind, message, atSimulationTimeS, atIso}` is set until the next success.

## Catalogue (M5)
`GET /api/v1/catalogue` (read-only; POST/PUT/PATCH/DELETE answer 405) returns `{notes: [string], entries: [Entry]}` with nine sourced single-body definitions: stars Sun, Proxima Centauri, TRAPPIST-1, Sirius A, Betelgeuse; planets Earth, Mars, Jupiter, Neptune.
`Entry = {id, name, kind: "star"|"planet", properties: {massKg: Property, radiusM: Property}, visual: {colorHex, note: "display only, not a physical property"}, notes}` and
`Property = {value (SI), uncertainty: {minus, plus} | {range: [lo, hi]} | null, basis: "measured"|"nominal"|"estimated"|"illustrative", sourceValue (as published, with unit), sourceNumber, sourceUnit, conversion, sources: [{citation, url, retrieved}], note?}`.
`estimated` (currently only Betelgeuse, whose mass is the midpoint of a published range, disclosed) and `illustrative` values must be disclosed wherever shown. Entries carry no positions or velocities, are not validated systems, and are copies: creating or editing a body never changes them. Values and sources are listed in `backend/catalogue_data.json` (built by `scripts/catalogue/build_catalogue.py`; `tests/test_catalogue.py` re-derives each value from its recorded source number). M☉ is converted with the IAU 2015 nominal GM☉ᴺ = 1.3271244e20 m³/s² divided by G; R☉ with the nominal 6.957e8 m.
Creating a body (`POST .../bodies`) may carry `kind` and `catalogueEntryId`; `kind` must be `star` or `planet` (422 otherwise), `catalogueEntryId` must name a catalogue entry (422 otherwise) and is provenance only. `PATCH` accepts `kind`. A body's `radiusM` is its physical (collision) radius; the 3D view draws bodies at an exaggerated display size that is never sent to or returned by the API.

### Withdrawn / planned
- `POST /simulation/start` and `/simulation/pause`: **not implemented and no longer planned**; Play/Pause is client-side scheduling of `step` requests.
- 🕓 Checkpoint save/restore: not specified (REBOUND restore works, but the resolver, ledgers and event log would have to be rebuilt; M0.6).

## Engine behaviour the client can rely on
- Newtonian point-mass gravity among all bodies, G = 6.67430e-11, IAS15 (adaptive). Radius matters only for collisions. No other forces, no relativity, no tides.
- Each `step` is integrated in chunks short enough that a_rel·dt²/8 ≤ 1% of each pair's contact distance (so `line` collision detection stays valid), at most 2000 chunks per request (beyond that chunks are longer than the criterion asks).
- Simultaneous collisions resolve in a fixed (seeded) order. A merge conserves mass and linear momentum to round-off (tested ≤ 1e-12 relative).
- Editing a body mid-simulation (mass/position/velocity/radius) restarts the integrator's internal state; conservation is not claimed across the edit itself.

## Physics limitations
- A merge does not conserve kinetic+potential energy or orbital angular momentum; the orbital part is bookkept as spin (`bookedSpinKgM2PerS`, `Event.spinAddedKgM2PerS`) but no spin dynamics exist. The cumulative energy-loss ledger (`heat_J`) is server-private and not exposed.
- Event times are detection times at integrator-step granularity; contact time is an estimate.
- `line` detection assumes near-straight motion inside a chunk. Stress-tested (P-003, `tests/test_stress_p003.py`): eccentric and grazing bound binaries (e up to 0.9), a hyperbolic flyby, 4–12 simultaneous collisions, mass ratios up to 2e30:1 and a 1e17:1 merger. Still untested: close three-body encounters against an independent high-resolution reference, tree collision modes, N beyond 200.
- Latency (measured 2026-10-24, one core, no collisions): N=100: 0.05 s for dtS=1e5, 2.0 s for dtS=1e7; N=200: 0.2 s for dtS=1e5 and >10 s (cut off by the budget, a 503) for dtS=1e7. The cost is ~2000 chunks × O(N²).
- **Binary64 mass resolution:** at mass ratios ≳ 1e16:1 the light body's mass is below the heavy body's ulp, so the remnant mass is not the exact sum (momentum is still conserved to round-off). The sum is exact while it is an integer number of kg below 2^53 (~9.0e15).
- Doubles resolve ~3e-5 m at 1 AU, limiting collision-geometry accuracy for small bodies far from the origin.
- Two centres coinciding exactly mid-step (measure zero) end in a merge or a rolled-back 500, never in silent corruption (tested for one geometry).
- Very small radii with very close non-colliding encounters can make IAS15 take very many tiny steps; the wall-clock budget turns that into a 503 instead of a hang.
- **REBOUND defect worked around (D-011):** with REBOUND 5.2.2's default step-size criterion a body whose net force cancels by symmetry (e.g. three equal masses at rest on a line) makes `integrate` never return. The service selects the GLOBAL criterion instead, which handles all tested symmetric layouts (lines of 3 and 5, 3x3 grid, ring, cube).
- State is in-memory, single process, lost on restart; no authentication; at most 200 bodies.

## Assumptions / known issues
- **Vite proxy mismatch:** `frontend/vite.config.ts` strips `/api` while the backend serves `/api/v1/...`; owned by the frontend session (T-008).
- Bounds on mass/radius/position are generous sanity limits, not physical claims.

## Collision engine: materials, spin and orientation (Stage 2, implemented; backward compatible)
- `GET /api/v1/materials` -> `{schemaVersion: 1, profiles: [MaterialProfile]}`: the immutable registry (silicate-rock, rubble-silicate, iron, water-ice, gas-envelope-hhe). Every number has a `provenance` entry; a missing quantity is absent and listed in `incomplete`.
- `POST /api/v1/bodies` and `PATCH` accept optional `material` (`{profileId, layers?}`), `spinRadPerS` (inertial frame, each component within 1e5 rad/s) and, on create, `orientation` (`{quaternion: [w,x,y,z], epochS}`). `PATCH` with `material: null` or `spinRadPerS: null` clears it.
- Responses carry `material`, `spinRadPerS` and `orientation` **only when set**; a body without them has exactly the previous JSON. `orientation` is the unit quaternion (body -> world) at the state's `simulationTimeS`, evaluated in closed form (constant spin, torque-free; approximation for non-spherical bodies).
- A spin or orientation needs a material whose profile has a sourced moment-of-inertia factor (I = k M R^2; currently the analytic uniform-sphere k = 0.4 for rock, rubble, iron, ice; none for the gas envelope). A body without a material never gets a spin state in any mode (D-033 DQ-2).
- Errors (HTTP 422, `{detail, code}`): `material_invalid` (unknown profile, bad layers), `rotation_requires_material`, `rotation_invalid` (non-unit quaternion). Malformed shapes are ordinary request-validation 422s.
- `diagnostics` keeps `version: 1`; the additive key `spinAngularMomentumKgM2PerS` (sum of I*omega) appears only while some body has a rotation state.
- A merger (either mode) books the spin angular momentum of the bodies into `bookedSpinKgM2PerS`, ends their rotation states, and keeps a material only if both bodies had the same one.
- Spin and material do not affect gravity (trajectories are bit-identical with and without them).

## Collision events and products (Stage 4a, implemented; only in mode outcome-v1, which no universe uses by default)
- `events[]` may contain, next to the unchanged `merger`, `{type: "collision", id: "col-<n>", outcome, simulationTimeS, estimatedContactTimeS, bodyIds: [target, projectile], survivingBodyIds, createdBodyIds, removedBodyIds, parentEventId, rootEventId, generation, modelId, modelVersion, impactSpeedMPerS, impactAngleDeg, specificImpactEnergyJPerKg, largestRemnantMassKg, debrisMassKg, massResidualRel, momentumResidualRel, warnings[], fidelitySummary{}, hasVisual, schemaVersion}`. `outcome` is one of perfect_merge, graze_and_merge, hit_and_run, partial_accretion, partial_erosion, cratering, catastrophic_disruption, super_catastrophic_disruption, envelope_deposition, envelope_merge_approximation. Event numbers (`evt-` and `col-`) share one counter.
- Bodies created by a collision carry optional `originEventId`; debris parcels also `representation: "debris-parcel"` and `debris: {totalMassKg, sizeDistribution: null, velocityDispersionMPerS, materialProfileId, sampleSeed}`. A parcel is a massive, gravitating body that stands for a population (statistical); in Stage 4a there is one parcel per event, with a placeholder launch speed (warning `debris_launch_speed_placeholder`).
- Warnings are stable codes, among them `provisional:CP-SCI-1` (the result depends on a provisional relation), `unsupported_regime`, `model_failed_fallback`, `spin_not_represented_fallback`, `debris_returned_to_remnant`, `remnant_spin_supercritical`, `remnant_spin_capped_at_breakup`, `envelope_dynamics_not_resolved`, `outside_calibration_velocity`, `hit_and_run_inelastic_normal_contact`, `projectile_erosion_not_modelled`.
- New error code `collision_unresolvable` (HTTP 500, step rolled back, state unchanged): only if every resolution tier fails (non-finite input).

## Collision engine — Stage 7 additions (debris lifecycle; all additive and optional)
- `POST .../step` response: `advancedS` is **no longer always dtS**: when the per-step collision-resolution budget (`maxResolutionsPerStep`, default 64) is reached the step ends at the current time (committed) and the response carries `warnings: ["collision_budget_reached"]`. The `warnings` key is absent when empty. Clients must use `advancedS`, not `dtS`, as the time advanced (DQ-10 (a), D-051).
- Body: optional `fragmentClass` ∈ `bound_to_remnant | orbiting_system | escaping` on fragments and parcels (computed from the present state by two-body energies; not a prediction). Absent for every other body.
- Diagnostics (still `version: 1`): optional `escaped` = `{massKg, momentumKgMPerS, angularMomentumAboutOriginKgM2PerS, bodyCount}`, present only after debris was removed by the escape rule (an escaping fragment/parcel beyond `escapeRemovalRadiusFactor` x the system extent). `totalMassKg` etc. describe the live bodies; live + escaped is conserved.
- `collision` events: `parentEventId`, `rootEventId`, `generation` are now filled for secondary impacts (a body created by an earlier event is involved); ordinary impacts keep `parentEventId: null`, `generation: 0`. Event warning `cascade_limit_reached` marks a non-fragmenting resolution forced by `maxFragmentingGeneration`.
- Resolved interactions: gravity between ALL bodies including fragments and parcels; contact between any two bodies through the collision pipeline (material-less pairs: the exact legacy merge). Approximated: the internal dispersion of a parcel; the energy leaving with removed debris is not tracked.

## Collision engine — Stage 8 additions (records, inspection, replay; read-only, additive)
- `GET /api/v1/universes/{uid}/collisions?limit=&offset=&rootEventId=&parentEventId=` → `{schemaVersion, universeId, total, offset, limit, maxRecords, records: [{eventId, legacyEventId, parentEventId, rootEventId, generation, outcome, modelId, modelVersion, timeS, bodyIds, warnings, hasResult, detailDropped, inputDigest, resultDigest}]}`, oldest first. A legacy-merge universe returns an empty list.
- `GET /api/v1/universes/{uid}/collisions/{eventId}` → `{schemaVersion, universeId, record, childEventIds, products, escapedLedger, note}`. `record` is the full `CollisionRecord` (input state and geometry, materials, model id/version/parameters, selection reasons, result with post states, mass ledger, conservation report incl. energy and angular momentum, warnings, fidelity, digests). `eventId` may be a `col-<n>` id or the `evt-<n>` id of the legacy `merger` event of the same physical event. `products` lists each product with its mass at the event, whether it still exists, its present mass and `fragmentClass`.
- `POST /api/v1/universes/{uid}/collisions/{eventId}/replay` → `{schemaVersion, universeId, eventId, reproduced, checks: [{name, ok|null, detail}], recordedResultDigest, replayedResultDigest, differingFields, mutatesState: false}`. A dry run: it recomputes from the record and never changes the universe or its revision.
- Errors: 404 `collision_record_not_found` (never existed or dropped; at most 1000 records are kept); 404 `universe_not_found`; 422 for out-of-range `limit`/`offset`.
- Results now carry `fieldsExtra.replay*` (the body budget, tier and permission used), needed to reproduce the realisation.
